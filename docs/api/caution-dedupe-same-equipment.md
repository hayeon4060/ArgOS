# 같은 설비 경보 중 주의 2중 알림 · 체크리스트 보낸 뒤 '주의' 단추 — 백엔드 요청 (2026-11-22)

프론트 브랜치 `feature/frontend-caution-button-dedupe`. **새 API · DB 변경은 없습니다.** 화면은 프론트에서 먼저 고쳤고, 백엔드에는 확인 1건 · 요청 2건입니다.

## 1. 무슨 일이 있었나

1. 체크리스트를 보낸 뒤(알림 `ACTING`) 상단 바 '주의' 상태 띠를 누르면 **체크리스트 진행 창**이 열렸습니다.
   체크리스트는 상단 바 '체크리스트 진행' 단추로 따로 볼 수 있으니, '주의' 는 **주의 상세**가 열려야 합니다.
2. 상도 건조로에 경보가 진행 중인데 같은 상도 건조로의 주의가 상태 띠 · 목록에 **또 따로** 나왔습니다 (2중 알림).
   예: 경보 상황에서 `CO 경보(1051)` · `전류 경보(1050)` 와 함께 `온도 주의(1049)` · 앞서 대응하던 `전류 주의(1042)` 가 같이 보임.

1번은 프론트만의 문제라 백엔드 할 일은 없습니다.

## 2. 프론트에서 한 것 (지금 서버 그대로 동작)

- '주의' 상태 띠 · 띠 목록에서 고른 주의: 조치 중이어도 **주의 상세** (`stores/alert.js openFor`)
  - 주의 상세는 보낸 체크리스트의 항목 · 받는 사람을 `GET /checklists/{id}` 로 채우고, 고칠 수 없게 잠금 (단추 '전송 완료')
  - 체크리스트 진행 창은 상단 바 '체크리스트 진행', 오늘 알림 내역의 '체크리스트 진행 보기' 에서 그대로 열림
  - 본사 관리자는 예전처럼 체크리스트 진행 창(열람)
- 같은 설비에 경보 · 화재가 진행 중이면 그 설비의 주의는 **상태 띠 · 띠 목록 · 새 알림 창 · 본사 알림 띠에서 뺌** (`stores/alert.js visibleAlarms`)
  - 같은 설비 판단: 알림 목록 줄의 `unitId`(관제 단위)가 같거나 `equipmentId` 가 같음
    (상도 건조로 센서는 배기팬 · 버너실에 나뉘어 달려 있어 `equipmentId` 만으로는 같은 건조로인지 알 수 없어서 `unitId` 를 먼저 봄)
  - 경보가 끝났는데 그 주의가 아직 '발생 중(OPEN)' 이면 그때 주의 알림 창이 뜸
  - 알림 데이터 자체(`GET /alarms`)는 그대로. 오늘 알림 내역 · 통계 · 이력에는 그대로 나옴

## 3. 확인 요청

중앙 서버 `AlarmCorrelator` 는 **관제 단위마다 열린 알림을 하나**만 두고, 같은 단위 센서의 새 이벤트는 그 알림에 붙여 단계를 올립니다.
그러면 같은 단위에서 경보와 주의가 따로 열리는 일은 원래 없어야 하는데, 아래 경우에는 생길 수 있어 보입니다. 실제로 생기는지 확인 부탁드립니다.

| 경우 | 왜 |
|---|---|
| 한 센서가 관제 단위 여러 개에 들어 있음 (`control_unit_sensor`) | `onEventOpened` 가 단위마다 알림을 엶 → 같은 설비에 단위별 알림이 따로 |
| 주의가 사람 손으로 닫히거나(`closeAlarm`) 체크리스트 확인 뒤 자동 종료된 직후 값이 다시 오름 | 그 단위의 다음 이벤트는 **새 알림**이 됨 |
| 한 설비(예: 상도 건조로)에 관제 단위가 둘 이상 | 단위가 달라 알림이 따로 열림 |

## 4. 요청

1. **같은 설비에 경보 · 화재가 열려 있을 때 새로 열리는 주의는 따로 알리지 않기**
   - 알림은 지금처럼 만들어도 됨 (이력 · 통계에는 남아야 함)
   - 대신 SSE `alarm.created` · 알림 목록 줄에 `coveredBy: <경보 alarmId>` (없으면 `null`) 를 주면, 프론트는 지금의 `unitId` · `equipmentId` 비교 대신 이 값을 씀
   - 공정 담당자 앱 푸시 · `GET /notifications/summary` 건수 · 대시보드 공장 현황의 주의 건수에서도 같은 기준으로 빼 주세요
2. **경보가 열릴 때 이미 열려 있던 같은 설비의 주의 처리 규칙 정하기**
   - (가) 주의는 그대로 두고 화면에서만 숨김 (지금 프론트) / (나) 경보 알림에 합치고 주의는 닫음 (`alarm_action` 에 `MERGED` 기록)
   - 정해지면 프론트는 (나) 일 때 숨김 코드를 지울 수 있음
