# 주의·경보 창 유형 문구 · 주의 상세 창 합치기 — 백엔드 전달 (2026-11-19)

프론트 브랜치 `feature/frontend-alert-merge`. **새 API · DB 변경은 없습니다.** 지금 응답으로 화면이 동작하고, 아래 2가지만 확인·요청드립니다.

## 1. 화면에서 바뀐 것

| 화면 | 변경 |
|---|---|
| 주의 알림 창 | '2단계 · 주의' → **'2단계 · 가스 주의'** / **'화재 주의'**, 제목도 '가스 주의 상태가 감지되었습니다' |
| 주의 상세 창 | 제목 '가스 주의 상세' / '화재 주의 상세'. 따로 열던 **'센서 데이터 · 열화상 확인' 창을 이 창에 합침** (센서 3종 값 + 열화상 1장 + 추이 1개) |
| 경보 대응 창 | '3단계 · 경보' → **'3단계 · 가스 경보'** / **'화재 경보'** |

유형 규칙은 통계·이력과 같습니다: 응답의 `hazard` 가 `GAS` 면 가스, `FIRE` 면 화재. `hazard` 가 없으면 화면이 센서 종류로 정합니다 (CO → 가스, 전류·온도 → 화재).

## 2. 쓰는 응답 필드 (지금 그대로 — 빠지지 않게만 해 주세요)

- `GET /alarms` items: `hazard`, `sensorType`
- `GET /alarms/{id}/detail`: `hazard`, `sensors[]`(센서 3종 tag·type·value·unit·warn·alarm·level), `thermal`(imageUrl·max·avg·usualAtMax·maxPoint·zoneName·cameraTag), `trend`, `fanAuto`
  - 합친 창은 이 응답 **한 번**으로 그립니다 (예전에는 두 창이 각각 한 번씩 불렀음)
- `GET /alarms/{id}/response`: `hazard`

## 3. 요청 (작은 것 1개)

- `GET /alarms/{id}/response` 의 `title` 에 유형을 넣어 주세요.
  - 지금: `상도 건조로에서 경보가 발생했습니다`
  - 요청: `상도 건조로에서 가스 경보가 발생했습니다` / `…화재 경보가 발생했습니다` (`AlarmService` 의 `a.unitName() + "에서 " + Codes.stageName(a.stage()) + "가 발생했습니다"` 자리)
  - 안 바꿔도 화면 위 작은 글자('3단계 · 가스 경보')에는 유형이 나옵니다.

## 4. 확인해 주세요

- 3단계 '화재 경보'(전류·온도 경보)와 4단계 '화재 발생'(열화상 화재 감지)은 다른 창입니다. 이름이 비슷해 헷갈리면 알려 주세요.
