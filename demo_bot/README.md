# ArgOS 시연용 센서 데이터 봇

터미널에 명령을 입력하면 시나리오 CSV를 **1초 간격**으로 **MQTT 브로커에 발행**합니다 (Node-RED가 구독해서 받음).
1초마다 **센서 7개**를 보냅니다.
- TE·IT·AT 6개(전착 건조로 TE-303·IT-303·AT-301, 상도 건조로 TE-305·IT-307·AT-303) → MQTT 브로커
- 열화상 IR-301 1개 → **VMS 서버**(`--vms-url`, 기본 `http://127.0.0.1:9000/ir`)로 HTTP POST. 봇이 카메라 역할이고, 단계 판정·ROI·스냅샷·메인 서버 전송은 VMS 서버가 맡습니다.

아무 명령도 없을 때는 정상 데이터를 계속 보냅니다.

## 설치
MQTT 전송에는 `paho-mqtt`가 필요합니다 (처음 한 번만).
```
python -m pip install paho-mqtt
```
`--dry-run`과 `--mode http`는 설치 없이 동작합니다 (Python 3 표준 라이브러리만 사용).

## 실행
```
cd 바탕화면\shy_ws\demo_bot
python demo_bot.py --dry-run                 # 전송 없이 보낼 토픽과 JSON을 화면에 출력 (점검)
python demo_bot.py                           # 기본 브로커 192.168.0.14:1883 으로 MQTT 발행
python demo_bot.py --host 192.168.0.20       # 다른 브로커
python demo_bot.py --mode http --url http://192.168.0.10:1880/sensors   # 예전 HTTP 방식
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--mode` | `mqtt` | `mqtt` 또는 `http` |
| `--host` / `--port` | `192.168.0.14` / `1883` | MQTT 브로커 주소 |
| `--qos` | `1` | MQTT QoS (0, 1, 2) |
| `--topic-base` | `argos/P5` | 토픽 앞부분 |
| `--username` / `--password` | 없음 | 브로커 인증 (환경변수 `ARGOS_MQTT_USER`, `ARGOS_MQTT_PASSWORD`로도 지정) |
| `--url` | `http://localhost:1880/sensors` | http 모드의 Node-RED 주소 |
| `--vms-url` | `http://127.0.0.1:9000/ir` | IR(열화상) 값을 보낼 VMS 서버 주소 |
| `--no-vms` | | IR을 보내지 않음 (TE·IT·AT만 전송) |
| `--only-ir` | | IR만 VMS로 보냄 (TE·IT·AT와 MQTT 브로커 없이 VMS 서버만 시험할 때. paho-mqtt 불필요) |
| `--interval` | `1` | 전송 간격(초) |
| `--dry-run` | | 실제 전송하지 않고 화면에 출력 |
| `--quiet` | | 매 전송마다 출력하지 않음 |

브로커와 연결이 끊기면 경고를 한 번 띄우고 자동으로 다시 연결합니다. 끊긴 동안의 데이터는 쌓지 않고 버립니다 (재연결 때 지난 데이터가 몰려 들어가 판정이 꼬이지 않도록).

## 명령어
| 입력 | 동작 |
|---|---|
| `전착_2단계` | 전착 건조로 **가스** 2단계 (AT-301 CO 17~24 ppm) |
| `전착_3단계` | 전착 건조로 **화재** 3단계 (TE-303 200 ℃ 이상) |
| `상도_2단계` | 상도 건조로 **가스** 2단계 (AT-303 CO 18~24 ppm) |
| `상도_3단계` | 상도 건조로 **화재** 3단계 (TE-305 160 ℃ 이상) |
| `q` (= `정상`) | 시나리오를 끝내고 정상으로 복귀 |
| `상태` / `도움말` | 현재 상태 / 명령어 |
| `나가기` (exit, quit) | 프로그램 끝내기 |

- 화재와 가스는 동시에 나오지 않습니다. 시나리오가 켜진 건조로의 센서 값만 바뀌고 나머지 센서는 정상으로 계속 전송됩니다.
- IR은 `상도_3단계`(화재)에서만 3단계 값(61~67 ℃)을 보내고, 그 밖의 시나리오와 정상에서는 정상 값(약 46 ℃)을 보냅니다.
- 시나리오 CSV는 5분(301행)짜리이고, `q`를 입력할 때까지 **반복 재생**됩니다.
- `q` 후 정상 값이 연속 20회(20초) 들어오면 시스템이 복귀로 판정합니다.
- `timestamp`는 바꾸지 않고 **CSV에 적힌 시각 그대로** 보냅니다. (CSV는 2026-11-16 09:02:10~09:07:10 구간이라, 5분마다 반복될 때 같은 시각이 다시 전송됩니다.)

## 전송 형식 (MQTT, 기본)
1초마다 **센서 1개당 메시지 1개**를 QoS 1로 발행합니다 (항상 6개).

| 센서 | 토픽 |
|---|---|
| TE · IT · AT | `argos/P5/paint/{센서종류}/{태그}` 예: `argos/P5/paint/TE/TE-305` |

```json
{"ts":"2026-11-16 09:02:15","type":"TE","serial":"TE-305","value":165.2,"unit":"℃","quality":"GOOD"}
```
- `unit`: TE `℃`, IT `A`, AT `ppm`
- `quality`: 항상 `GOOD` (시연 봇은 센서 고장을 흉내 내지 않음)
- 받는 쪽 Node-RED에서는 `mqtt in` 노드로 `argos/P5/#`를 구독하면 전부 받을 수 있습니다.

## 전송 형식 (IR → VMS 서버)
1초마다 IR-301 값 1건을 JSON으로 `POST` 합니다 (TE·IT·AT와 같은 형식, `stage`는 VMS가 판정하므로 없음).
```json
{"ts":"2026-11-16 09:02:10","type":"IR","serial":"IR-301","value":61.2,"unit":"℃","quality":"GOOD"}
```
- IR은 MQTT·Node-RED(`--mode http`의 `--url`)로는 가지 않고 `--vms-url`로만 갑니다.
- VMS 서버가 꺼져 있으면 경고를 한 번 띄우고 계속 재시도합니다 (끊긴 동안의 데이터는 버립니다).

## 전송 형식 (HTTP, `--mode http`)
1초마다 센서들을 한 번에 JSON 배열로 POST 합니다.
```json
[{"timestamp":"2026-11-16 09:02:15","sensor_type":"TE","sensor_serial_no":"TE-305","value":165.2}, ...]
```
`nodered_flow.json`을 Node-RED에서 가져오기(Import)하면 `POST /sensors`를 받아 센서별로 나눠 debug에 보여 주고 200 응답을 돌려줍니다.

## 시나리오 규칙 (기준값은 7일 더미데이터 평균)
- 가스 2단계: CO 15 ppm 이상 30 ppm 미만 (IT는 정상)
- 화재 3단계: TE가 설정온도 +20 ℃ 이상 (전착 200 ℃, 상도 160 ℃)
- 2단계 연속 15회(15초), 3단계 연속 15회(15초), 복귀 연속 20회(20초) 정상

## 폴더 구성
```
demo_bot.py            봇 본체
nodered_flow.json      Node-RED 수신 예제 플로우 (HTTP 모드용)
scenarios/정상/         정상 7개 센서 (IR 포함)
scenarios/전착_2단계(가스)/  전착_3단계(화재)/  상도_2단계(가스)/  상도_3단계(화재)/   (상도_3단계(화재)에는 IR 3단계 CSV 포함)
```
새 시나리오는 `scenarios/중도_3단계(화재)`처럼 폴더를 추가하고 센서 CSV를 넣으면 됩니다 (폴더 이름의 괄호 앞부분이 명령어가 됩니다. 단, 명령 해석은 전착·중도·상도 + 숫자 + 단계 형식입니다).
